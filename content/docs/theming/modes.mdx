---
title: Modes in CSS
description: How the generated stylesheet composes the five settings.
---

Each setting has its own attribute, `data-sp-mode-<setting>="<value>"`. Each setting is carried by inherited toggle variables, such as `--_sp-not-style-helios`. An attribute sets only its own setting's toggles on its element and leaves every other setting inherited.

A token whose value differs by mode is one expression that picks its value from the toggles. It is declared again wherever a setting it depends on can change, because `var()` resolves where it is declared.

## Consequences

- Settings are independent at any depth. A nested element that sets only the color scheme keeps the page's style, contrast, hue, and density.
- Any number of settings can matter to one token, and they can be set on different elements. There are no compound selectors.
- Opacity primitives are percentages, and alpha-bound colors become `color-mix(in srgb, <color> <opacity>, transparent)`.
- The toggles use empty custom property values. The project verified them in Chromium only.

## Nested settings

```html
<html data-sp-mode-color-scheme="Dark" data-sp-mode-contrast="High">
  <aside data-sp-mode-color-scheme="Light"> <!-- Light inside, still high contrast -->
    <sp-button>Light panel button</sp-button>
  </aside>
</html>
```

The full reference, including the migration table, is `tokens/figma/README.md` in the repository.
