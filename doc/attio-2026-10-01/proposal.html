01 / Recommendation

Keep the color. Rebalance the surroundings.

Spartant’s pale dark-mode primary is a verified semantic mapping choice. Start by correcting solid-fill state mappings, then tighten neutral surfaces and menu anatomy. Much of the required density system already exists.

Verified in Figma

The primary jumps two steps lighter

color/primary/default maps to 600 in Light and 400 in Dark. Blue resolves to #006DCE → #6AAEFF. Dark hover uses 300 and active uses 200, becoming progressively paler.

Observed in Attio

Blue stays saturated

The same chart fill sampled approximately #276CF1 in both themes. Blue selection marks also retain their visual weight. Appearance’s cyan, orange, purple, and green swatches change, so this is not evidence that every accent is invariant.

Verified in Figma

The menu needs a structural pass

The inspected Dropdown Menu has 24 px shell padding, 12 px gap, and preset 160/200 px heights. Attio’s view menu is a compact list with about 4 px outer padding and 32 px rows.

Recommended direction: stable, saturated emphasis fills; theme-specific text colors; quieter surface steps; compact desktop controls; menus composed from reusable items. Keep secondary actions neutral and retain separate control-color roles.

Scope: research and proposal only. No Figma variables or components were changed. Attio was returned to Light mode. “GitHub structure” is interpreted as Primer’s token architecture and component documentation pattern, with a reviewable implementation backlog.

05 / Primer structure

Adopt the separation of responsibilities

GitHub Primer separates base, functional, and component/pattern tokens. Components use meaningful roles; raw colors remain behind those roles. Its semantic system distinguishes foreground, muted backgrounds, and emphasis backgrounds with a paired on-emphasis foreground.

1. Primitivecolor/primary/600Raw palette value; brand axis
→
2. Semanticcolor/primary/defaultPurpose and light/dark pairing
→
3. Componentbutton/primary/backgroundOnly if a distinct contract needs it

The third name is illustrative, not an instruction to add a duplicate token. Keep existing Spartant names and IDs wherever their meaning is correct. Add a token only when a consumer audit identifies a real missing role.

Keep or clarifyPurposeMigration rule
primary/default + hover + active + foregroundSolid emphasis contractAudit Button, Icon Button and all other consumers before repointing. Update fill and label pair atomically.
primary/text + primary/surfaceReadable colored text and soft backgroundsDo not merge with the solid action contract.
control/* + switch/thumbSelection controls, independent customizationPreserve override separation and dedicated thumb color.
surface/default, subtle, muted, elevatedCanvas, inset/support, container, overlay rolesWrite placement rules first. Add shell/inset/overlay only if existing roles cannot be made unambiguous without breaking consumers.
border/subtle, default, strong, overlayDecorative structure versus essential control boundariesDocument allowed background pairings and minimum-contrast cases.
shadow/control/* and future overlay shadow rolesTheme-aware elevationEvery effect layer remains bound to semantic color and opacity variables.

Document each component like a small, reviewable contract

Use Overview, Anatomy, Variants and sizes, States, Keyboard behavior, Accessibility, Token mappings, and Migration notes. Link Figma evidence to implementation status. An approved Figma state is not evidence of implemented browser behavior.

References: Primer token naming, Button documentation, ActionMenu composition. Borrow the organization while retaining Spartant’s public API and visual identity.

Observed interaction evidence: typing “country” reduced the attribute list to the Primary location → Country result. Escape dismissed the panel. In Profile’s simple select, Down moved focus to Saturday; Escape closed without committing and restored focus to the Monday combobox. Focus restoration for the richer configuration panel was not confirmed by its accessibility output.

Keep animation small: propose 120–160 ms opacity and 2–4 px travel from the anchor, with no animated layout growth. Respect reduced motion. These are proposed timings, not measured Attio values.

Reference: Primer ActionMenu accessibility. Searchable selectors and configuration popovers require their own interaction contracts.

08 / Borders, shadows, type

Make depth specific to the surface

Attio’s light buttons have a faint edge and short contact shadow; popovers have a broader shadow. In Dark, a slight surface lift and a thin edge do more of the separation. Large dashboard cards rely mainly on borders. The effect should communicate hierarchy rather than decorate every container.

Definition of done

  • Primary action has consistent saturated emphasis in the same light/dark composition; hover and press do not drift toward pastel.
  • Text pairs reach 4.5:1 for normal text, and essential non-text states meet 3:1 where applicable. Focus remains visible without relying on a diffuse shadow.
  • Surface roles have documented placement and approved pairings. High contrast is assessed independently of the standard aesthetic.
  • Dropdown supports keyboard opening, navigation, dismissal, focus return, scrolling, edge placement, long labels and an empty search result.
  • Figma variants remain connected and every changed color/effect is semantically bound. Code receives appropriate interaction checks once its working source is available.

Recommended first review

Approve one narrow experiment: stable solid primary fills, current versus candidate dark surfaces, and a compact dropdown shell on three small comparison compositions. Review those together before changing shared library variables. The proposal does not authorize or perform a production migration.
