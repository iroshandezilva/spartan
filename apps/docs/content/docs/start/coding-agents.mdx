Spartant is built with coding agents as a first-class audience. This page is
the contract: what an agent can read, what it can import, what it must not do,
and how it proves its work. Everything here is also true for a person.

## Machine-readable entry points

| Path | Holds |
| --- | --- |
| `/llms.txt` | The index: every published page with its description, grouped by section, preceded by the source-of-truth order, the stop conditions, the stable commands, and links to the repository files that have no page of their own |
| `/llms-full.txt` | Every page as one Markdown document in navigation order, with the tables this site generates from the token JSON rendered as Markdown tables and the Storybook coverage tables included |

Both are generated at build time from the same page tree this site renders,
so neither can fall behind the site, and the guidance below is printed from
the same constants `/llms.txt` prints. Live interactive examples have no text
form; the full text says so where each one sits. The prompt set that proves an
agent can answer from these files alone is on
[Agent evaluation](../contributing/agent-evaluation.mdx).

## Stable commands

All run from the repository root through pnpm. Never npm or yarn; a
`preinstall` guard fails the install if you try.

| Command | Does |
| --- | --- |
| `pnpm validate` | The full gate: format, lint, doc links, token checks, colour checks, type check, tests, story tests, build, package inspection. Run it before claiming work is complete |
| `pnpm typecheck` | Project references, then the test files |
| `pnpm test` | Vitest, Node only. Builds the package first |
| `pnpm test:stories` | Renders every story, runs its play function, audits it with axe |
| `pnpm check:tokens` | Validates the token sources and proves emission |
| `pnpm check:colors` | The contrast and gamut audit over both themes |
| `pnpm build:docs` | Builds the package, then this site |
| `pnpm dev:storybook` | The workbench on port 6006 |
| `pnpm dev:docs` | This site on port 3100 |
| `pnpm smoke:package` | Packs the package and installs the tarball in a throwaway project outside the workspace |

## Rules an agent must follow

These are the rules that most often go wrong. `AGENTS.md` is the full list.

1. **Semantic roles only.** `bg-primary`, `text-foreground-muted`,
   `border-border-strong`. Never a raw value such as `bg-[#3b5bdb]`, never a
   palette step. Primitives are not emitted as custom properties, so reaching
   for one is impossible by design and a sign the design is being fought.
2. **Motion through tokens.** Durations, easings, distances, and scales come
   from the roles on [Motion](../foundations/motion.mdx). Keyboard activation
   is immediate. Focus, announcements, validation, and state never wait for an
   animation.
3. **Compose classes with `cn` and put the caller's `className` last**, so it
   overrides.
4. **Variants are a plain `Record<Variant, string>`** of complete class
   strings. No variant library.
5. **No new dependencies without an issue.** Animation libraries in particular
   need a justification covering behaviour, bundle impact, cleanup, server
   rendering, reduced motion, testing, and the consumer contract.
6. **No SCSS, no StyleX, no whole-catalogue shadcn import.** Adopting a single
   shadcn source file follows `ADOPTING-SHADCN.md`.
7. **Never expose a primitive library's API** through public props.
8. **Keep source, exports, stories, documentation, tests, and release notes
   synchronized** in the same change.
9. **No em dashes** anywhere in the repository's writing, including comments
   and commit messages.

## Token names an agent will need

Every semantic token is exported as `semanticTokens`, a map from token path to
custom property, and `tokenVar(path)` returns the `var()` reference. The path
is stable; the property name is derived from it mechanically:

```ts
import { semanticTokens, tokenVar } from "@iroshandezilva/spartant";

semanticTokens["color.foreground.muted"]; // "--spartant-color-foreground-muted"
tokenVar("radius.control"); // "var(--spartant-radius-control)"
```

`SemanticTokenPath` is the union of every valid path, so a typo is a compile
error. The full role tables are on [Tokens](../foundations/tokens.mdx) and
[Color](../foundations/color.mdx).

## Verification an agent must run

Run the checks named in the Linear issue. At minimum, work that touches a
component should run `pnpm validate`. Never report a check as passing when it
was not run, and explain every omitted check that would normally apply.

Manual testing is required whenever a change affects keyboard navigation,
focus, screen readers, pointer or touch behaviour, theme appearance,
responsive or long-content behaviour, animation, reduced motion, package
installation, or production deployment. `MANUAL-REVIEW.md` is the checklist;
its result block is pasted into the Linear comment and the pull request. When
the environment supports the check, the agent performs it and records the
evidence. When only a person can, the issue moves to `Agent Done` with
`Human input required` and an exact checklist.

## Completion report

Every finished issue ends with the same structure, in the final response and
in the Linear comment:

```md
### Completed
### Changed
### Automated verification
### Manual verification
### Risks and follow-ups
```

The headings and their expected contents are defined in `AGENTS.md`.

## Known gaps

- The source-of-truth order and the stop conditions above are copied from
  `AGENTS.md` into this site's source so the site can answer without a
  checkout. `AGENTS.md` wins if they ever differ, and a change there is made
  here in the same pull request.
- `/llms-full.txt` renders the generated tables, but not the specimens that
  only make sense drawn: the type specimens, the spacing bars, the radius
  boxes, and the easing curve plots. The text says so where each sits and the
  values are in the table beside it. An agent that wants the raw data reads
  `@iroshandezilva/spartant/tokens.json`, which is the same source.
- Component pages describe each component's public API prop by prop, its
  keyboard behaviour, its motion contract, and its token dependencies. The
  authoritative machine-readable form of the motion and accessibility
  contract is still the `contract` object in each story file under
  `apps/storybook/src/stories/`, which the pages are written to agree with.
