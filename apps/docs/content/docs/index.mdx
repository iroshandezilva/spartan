Spartant is a personal, code-first React design system for building consistent
product prototypes quickly. It is distributed as one npm package,
`@iroshandezilva/spartant`, and it owns its component source, its public API,
its tokens, and its themes. Nothing in it is a wrapper around another
component library.

## What it promises

- **Semantic tokens.** Components consume roles such as `primary` and
  `foreground-muted`, never raw colours or palette steps. A theme change or a
  consumer override retypes everything at runtime, with no rebuild.
- **Light and dark from one palette.** One OKLCH scale serves both themes;
  what changes is which step a role points at. Every required text and state
  pairing is contrast-checked in both themes on every build.
- **Accessible by default.** Native elements where they work, a 44px touch
  floor on every actionable control, one focus treatment everywhere, and
  reduced motion handled globally rather than per component.
- **Purposeful motion.** Every component records a motion purpose or an
  explicit no-motion rationale. Keyboard activation never waits for an
  animation.
- **Agent-readable.** Source paths, exports, commands, token names, and
  verification steps are documented so a coding agent can work from the
  published documentation alone. See [Using with a coding agent](./start/coding-agents.mdx).

## What it is not

- Not a framework. The package targets any React 19 renderer and ships no
  bundler assumptions. It has two runtime dependencies, `clsx` and
  `tailwind-merge`.
- Not a Tailwind requirement. A precompiled stylesheet is one of the two
  supported styling paths. See [Installation](./start/installation.mdx).
- Not a large catalogue. The v0.1 inventory is deliberately small and every
  component in it is owned source.

## What is released today

Every component in the approved v0.1 inventory is built: `Badge`, `Button`,
`Card` and its parts, `Checkbox`, `Dialog` and its parts, `Field`,
`FieldMessage`, `Input`, `Label`, `Popover` and its parts, `Radio`,
`RadioGroup`, `Select`, `Separator`, `Switch`, `Tabs` and its parts,
`Textarea`, and `Tooltip` and its parts, together with `ThemeProvider`,
`useTheme`, `themeScript`, `cn`, and the generated token surface. Each has a
page in [Components](./components/button.mdx). The full runtime export list is
generated from the package on
[Using with a coding agent](./start/coding-agents.mdx#what-the-package-exports).

<Callout type="warn">
  The package has not been published, so every component is prerelease and
  every component page says so. Tooltip and Popover are complete in the
  repository and pass every automated check, but their build issue is awaiting
  a manual keyboard and VoiceOver review; their pages record exactly what is
  still unverified.
</Callout>

## Known gaps

- The package has not yet been published to the npm registry. Its version is
  `0.0.0` and the install command on the next page describes the intended
  path. Publishing is its own issue.
- Component pages link to Storybook coverage by file path and story name,
  because there is no hosted Storybook. The static build is a CI artifact.
- Search uses the built-in static index. Token names and prop names are
  indexed through page keywords, but the index has not been evaluated against
  every task the documentation plan lists.
